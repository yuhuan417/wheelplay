# 浏览器音频与麦克风

CarPlay 音频始终只发送到当前车机浏览器，Android 不再本机播放，也没有回退扬声器。可在 Android App 的「设置 → 画面与音频」启用或禁用「浏览器麦克风」；修改后重新连接以更新 iPhone 的能力协商，禁用时停止上传并移除麦克风输入能力声明。Android 不采集自己的麦克风。页面显示当前路由；浏览器未就绪或离线时没有声音或输入。浏览器可能要求点按画面以启动音频播放。浏览器音频与视频传输独立；视频和浏览器麦克风都要求可信 HTTPS。

浏览器麦克风需要可信安全上下文。普通局域网 `http://设备地址:8080` 页面不能申请麦克风权限。配置步骤：

1. 在「设置 → Web 监听」打开「启用 HTTPS」。在「设置 → 权限与连接帮助 → 浏览器 HTTPS 证书」查看本设备的 SHA-256 指纹。在车机页面展开「浏览器麦克风/视频需要 HTTPS」，等待页面显示指纹并逐字核对，然后下载本地证书。
2. 在车机浏览器或系统中按其支持的方式信任此证书。随后打开页面提供的 `https://设备地址:HTTPS端口/` 链接（默认 `8443`）。
3. 在 App「麦克风来源」选择「浏览器麦克风」，重新连接 iPhone，并按浏览器提示授权。仅在 iPhone 发起通话或语音输入并要求麦克风数据时，浏览器采样才会发送到服务端；Android 不提供麦克风回退。

## 显示和离线行为

「CarPlay 昼夜模式」可选始终日间、始终夜间，即时发送给 iPhone，并在下一次会话重新应用。「画面安全区域」可预览和设置四边 0–40% 留白，按协商画面比例缩放，保存后重新连接；也可恢复全屏。留白控制 iPhone 的布局安全区域，触控仍使用完整画面坐标。旧版按分辨率保存的安全区域保留至用户修改。

「设置 → 浏览器行为 → 浏览器离线后的处理」默认保持 CarPlay，可选择等待 1 或 5 分钟后断开 iPhone。会话启动时没有浏览器也会开始计时；浏览器连接会取消计时，下一次离线重新计时。计时关联当前 iPhone 会话，旧计时器不会断开替换后的会话。超时只关闭 CarPlay，Web 服务继续提供设置和连接页面。

证书的私钥只保存在 Android 应用的私有、非备份存储中。默认 HTTPS 证书包含启动时的局域网地址，以及配置的共享 IP/域名。共享 IP/域名修改后自动刷新默认服务器证书；其他局域网地址变化后请重新启动服务。如果车机浏览器不能信任本地证书、禁用了麦克风权限或不支持 AudioWorklet，则无法使用浏览器麦克风。请勿通过浏览器的证书警告强行继续访问。

## Web 监听与 HTTPS 证书

「设置 → Web 监听」包含 HTTP 端口（默认 `8080`）、Web 域名和 HTTPS 开关，无需 Root。Web 域名同时用于 HTTP 与 HTTPS，DNS 需解析到实际访问 IP。HTTPS 使用 App 管理的本地证书；启用 Tesla 兼容中的 DuckDNS 后，签发的 Let's Encrypt 证书会自动替换它。HTTPS 默认开启；关闭后停止 TLS 监听，隐藏 HTTPS 端口，保留证书与端口配置，HTTP 继续可用。

开启 HTTPS 后可修改「Web HTTPS 端口」（默认 `8443`）。HTTP / HTTPS 实际监听端口范围均为 `1024–65535`，两者不能相同。运行中先绑定新端口；占用或绑定失败会保留原监听器和保存值。成功后浏览器需重新连接，iPhone 媒体会话保留；网页的「打开 HTTPS 页面」同步使用新端口。设置重启后仍有效。

使用 `80` / `443` 等低位端口时，在「设置 → Tesla 兼容（实验）」第一行请求 Root 权限。授权成功后显示映射端口与访问 IP 设置；开启系统热点及此模式后，通过 Root 将访问 IP 的低位端口转发到 Web 监听高位端口。映射规则与热点路由统一安装和清理，失败不影响普通 Web 服务。普通 App 直接绑定低位端口可能得到 `EACCES`，仅对路由 shell 授权不会改变 App 进程的绑定权限。详见 [Tesla 兼容说明](TESLA_HTTP.md)。

「Web 监听」不再提供证书类型选择，也不导入 PEM / PKCS#12。HTTPS 始终使用 App 私有存储中的本地 CA 证书；启用 DuckDNS 自动证书后，ACME 签发结果会安装为当前 HTTPS 身份。

本地 CA 证书包含启动时的局域网地址、配置的共享 IP 和可选域名。共享 IP / 域名修改后会自动刷新；其他局域网地址变化后请重新启动服务。使用 DuckDNS 时，证书必须覆盖配置的域名，解析地址与 Tesla 兼容的访问 IP 共用。

## 音频行为

浏览器媒体播放跟随 App 的「音频缓冲」设置，支持 300 / 500 / 1000 ms，默认 300 ms。首次播放和缓冲耗尽后的恢复都采用所选延迟。修改设置会同步给已连接的浏览器，重建媒体播放缓冲；原有 iPhone 重新连接行为保留。通话、导航和其他非媒体音频继续采用短缓冲，麦克风采样不受此设置影响。

服务端按各音频流的 PCM 时长限制待发队列：媒体最多保留所选缓冲加 200 ms，待发超过此时间的帧过期；非媒体音频保留 100 ms。队列还有 128 帧总上限，四帧等待确认。浏览器允许媒体突发包在所选缓冲上方保留最多约一秒余量；超过积压限制时丢弃新到音频，不再清空已经排队的声音。视频帧仍与音频共用连接，持续网络拥塞或超过缓冲时长的停顿仍可能造成断续。

浏览器麦克风发送 20 ms PCM 帧，并在服务端沿用 CarPlay 加密音频上行链路。实际车机对证书安装、音频焦点、回声消除与延迟的支持仍需分别验证。
